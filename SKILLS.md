## 20. Windows Registry Forensics From Scratch

## 27. Steganography & Steganalysis From Scratch
Hide data in images and detect it statistically — the full arms race, hand-built: hand-rolled 24-bit BMP codec (BGR order, row padding, bottom-up rows), LSB embed/extract with length+CRC32 framing in sequential and password-seeded spread (Fisher–Yates) modes, chi-square PoV attack with a hand-written regularized-gamma p-value, RS analysis (Fridrich–Goljan–Du, implemented from patent US6831991B2: M/−M masks, LSB-flipped dual image, the quadratic, smaller-|root| rule), and smooth-region LSB-agreement scoring. DCT-domain module: hand-rolled orthonormal 8×8 DCT-II/IDCT, IJG luminance quantization, F5-style embedding (decrement-|c| with shrinkage) vs Jsteg-style (naive LSB replacement), chi-square on coefficient histograms, and a lite "Breaking F5" calibration attack (decompress → crop 4px → requantize, odd/even balance). The `stegdetect` CLI triages any BMP: chi-square scan (localizes sequential payload ends), RS rate estimate, verdict line. Earned insights, all measured: chi-square is blind to spread embedding and to F5 (F5 shifts histograms toward evens instead of equalizing PoVs — chi2=0.0000 at every payload size); RS fails *honestly* on sequential embedding (model violation → negative discriminant → returns 0.0, no false confidence) and degrades near p≈1; chi-square false-positives on noisy covers (σ=6 noise gave P(embedded)≈1.0 on a clean image) and is unstable on small samples (933 DCT coefs: 0.31–0.95 across messages at 86% Jsteg capacity); the paper's "R_M=S_M at 50%" assumption is in flip-probability coordinates, not message-length — my first simulation "disproved" it by mislabeling the x-axis. Debugging wins: F_−1 implemented backwards (=F_1 again, caught because R_M==R_−M to 3 decimals), d1/d_−0 swapped (patent text settled it), BMP vertical flip (assert pixels, not dims). Validated 37/37 deterministic checks. The tool for "is there a hidden message in this image" — pairs with the image-forensics and QR skills for vetting suspicious files.

## 31. Coverage-Guided Fuzzing From Scratch
An AFL-style fuzzer built with zero dependencies: edge coverage via `sys.monitoring` BRANCH events (hashed to 64-bit), AFL-style hit-count bucketing (so loop counts and recursion depth become visible coverage — pure edge coverage is blind to depth), fork-server-lite runner with SIGALRM watchdog (ok / expected / crash / hang classification, ~250–650 exec/s), favored-entry power schedule, deterministic bitflip + integer-arithmetic stages, stacked havoc mutations (bit/byte flips, boundary values, chunk delete/clone, dictionary, splice crossover), seed trimming, traceback-frame crash dedupe, and ddmin-lite minimization. Earned insights: a one-line harness bug (`data not in self._seen_inputs` checked *after* every input was already added) silently disabled queue growth across 70k execs — caught only by watching the queue-length invariant; deterministic stages must respect the campaign budget or one big seed starves everything; blind mutation hits a wall on magic-gated formats (70k PE mutants, zero new coverage — the deterministic walks are what punch through).
