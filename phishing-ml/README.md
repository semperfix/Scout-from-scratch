# ML Phishing/Scam Detection (from scratch)

Everything here is hand-built: no sklearn, no torch. The point was to learn what
statistical learning actually *is* by deriving it — gradient descent from the
cross-entropy formula, Naive Bayes from Bayes' rule, AUC from the Mann-Whitney
integral — then aim it at a real operator problem: **is this URL / message trying
to scam me?** The `phishcheck` CLI scores a URL or message, prints the top
contributing features, and layers deterministic rule flags (typosquat, punycode,
brand-as-subdomain) on top of the learned model.

## Dependencies

- **Python 3** (3.10+ recommended)
- **numpy** (`pip install numpy`) — used by `ml.py` (model math) and `triage.py`
- Everything else is stdlib.

## Training data (re-fetch to retrain)

The repo ships `models.json` — **pre-trained model weights (156 KB)** — so
`triage.py` works out of the box without the raw data. The large raw datasets
were intentionally dropped from the repo; to retrain, re-fetch from the original
sources:

- **Malicious URLs** — [abuse.ch URLhaus](https://urlhaus.abuse.ch/) recent CSV feed
- **Benign URLs** — [Tranco](https://tranco-list.eu/) top-site list
- **SMS spam/ham** — [UCI SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection)

`data.py` consumes these feeds plus a documented synthetic brand-phish augmenter
(`synthetic_brand_phish()`) that generates clearly-labeled brand-impersonation
URLs (one-edit typos, brand-as-subdomain, risky TLDs) — the fix for a measured
distribution mismatch where URLhaus "recent" is almost all malware-download URLs
and brand phish barely exists in it.

## How to run

**Score a URL or message** (entry point `triage.py`):

```bash
python3 triage.py url  https://paypa1-login.verify-account.top/signin
python3 triage.py text "CONGRATS! You've won a $1000 gift card, claim now at ..."
```

First run loads `models.json` (ships pre-trained). Retraining on the feeds takes
~2 minutes and re-caches to `models.json`.

**Run the test batteries:**

```bash
python3 test_ml.py     # 47 fast unit checks (gradient check, AUC cross-check, CV)
python3 test_real.py   # slow end-to-end: real-data training, adversarial phish vs legit
```

## Example

```bash
$ python3 triage.py url https://paypa1-login.verify-account.top/signin
URL: https://paypa1-login.verify-account.top/signin
score: 0.800  ->  SUSPICIOUS
  [RULE] TYPOSQUAT: "paypal" at distance 1 + lure/risky-TLD  (floor 0.80)
typosquat: closest brand "paypal" at distance 1
lure words: account, login, signin, verify
```

Verdicts: `MALICIOUS` (≥0.85), `SUSPICIOUS` (≥0.60), `WORTH-A-LOOK` (≥0.35),
`CLEAN` (<0.35).

## Key learnings

- **The model learns the dataset's biases, not the concept.** First run hit
  accuracy 0.985, AUC 0.9998 — and was useless. *Looking at the weights* found two
  leaks: benign rows were synthesized as `http://domain`, so the model learned
  `is_https => malicious`; and URLhaus "recent" is all bare-IP malware URLs, so
  typosquat/lure features got near-zero weight. Metrics never showed this.
- **Distribution mismatch is the silent killer.** URLhaus barely contains
  brand-impersonation phish, so a hand-crafted `paypa1-login…` phish scored *lower*
  than `nytimes.com`. Fixed with a labeled synthetic brand-phish augmenter and
  disjoint adversarial evaluation URLs (never generator outputs).
- **Deterministic rules beat pretending.** A rule layer floors the score with the
  rule named verbatim (credentials-in-URL, typosquat+lure, punycode+lure, IP+odd-port)
  — explainable, not pretending to be learned. Rules fired on 8/8 hand-written phish,
  0/6 legit URLs.
- **AUC can be brute-force verified.** The test battery includes a 200-trial
  brute-force cross-check of the tie-corrected AUC against the Mann-Whitney integral.

## Files

| File | What it does |
|---|---|
| `triage.py` | **Entry point**: `phishcheck` CLI — score a URL or message, print top contributing features + rule flags |
| `features.py` | 30 hand-engineered URL features + true Damerau-Levenshtein typosquat distance vs ~150 brands (banded early-exit) |
| `data.py` | Real feeds: URLhaus CSV (malicious) + Tranco top list (benign) + UCI SMS corpus; synthetic brand-phish augmenter |
| `ml.py` | `Standardizer`, `GaussianNB`, `LogisticRegression` (full-batch GD, L2, 1/√t decay, early stopping), `CountVectorizer`, `TfidfTransformer`, `MultinomialNB`, metrics (confusion, P/R/F1, ROC-AUC, PR-AUC), stratified k-fold CV |
| `models.json` | Pre-trained URL + text model weights (ships with repo; re-generated by retraining) |
| `test_ml.py` | Fast unit battery (distance, features, gradient check, model units, metrics, CV) |
| `test_real.py` | Slow end-to-end: real-data training, adversarial hand-crafted phish vs legit |
| `metrics_run.txt`, `metrics_run2.txt`, `retrain_eval.txt`, `test_real_out.txt` | Recorded metrics from training/eval runs |

## Dropped from the repo

`url_dataset.pkl` (28 MB), `tranco.zip`, `urlhaus.csv`, `sms.zip`, `smsdata/` —
raw training data, too large for the repo. Re-fetch from the sources above to
retrain; `models.json` keeps the CLI working without them.

## Honest limitations

- Benign rows are domain homepages (no paths); path-shape features are inflated
  on the malicious side. Scores are one signal, not a verdict.
- 4,000 of ~30,000 malicious training rows are synthetic (labeled as such in code).
- SMS spam corpus is from 2012-era messages; modern smishing slang drifts.
- No JavaScript/HTML content analysis — URL + text only.
- Linear model: can't learn feature interactions (e.g. "typosquat AND lure-word
  together is worse than the sum").
